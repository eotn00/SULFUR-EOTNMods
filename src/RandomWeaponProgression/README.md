# 更rpg的火湖 2.0

## 属性与升级

对有位阶的非投掷、非近战枪械生效。每把枪拥有独立 UUID；同型号也不会共用词条。

- 初始五项：伤害、射速、换弹速度、精准、后坐力控制，各自随机 -15% 至 +15%。
- 每级随机提升 1 至 2 项不同属性，每项默认 +2% 至 +6%。
- 精准正值减少散布，控枪正值减少后坐力；负值反向影响。
- 初始属性与升级累计相乘；升级自身按累计百分比计算。
- 记录历史最高位阶的收益，降级再升回不会重新抽取。一次获得多级会逐级记录。
- 最多记录 1000 级，超过后仍保留已有收益，不继续增加历史。

配置文件：`BepInEx/config/local.sulfur.randomweaponprogression.cfg`。
Mod 设置分类为“更rpg的火湖”。数值设置仅影响以后新生成的记录；已有武器的初始结果、升级规则和历史不会因修改设置而重抽。
关闭总开关会暂停效果，但保留编号和记录。

## 枪械信息面板

在原有枪械属性、附魔和配件下显示：

1. 初始随机属性，以及编号的前 8 位。
2. 升级累计和已记录级数。
3. 逐级升级记录，最新等级在最上方。

历史区采用固定高度滚动列表，最多同时显示 4 行，并只渲染可见行，避免高等级撑出屏幕。
沿用游戏信息面板的交互规则，面板需要可交互时才能拖动滚动条。

## 从旧版迁移

插件文件为 `更rpg的火湖.dll`，替换旧名称 `RandomWeaponProgression.dll`。不要同时保留这两个文件。
新版替换 `RankBonuses.dll` 和 `SingleWeaponSaveTest.dll`。原“武器拓展/武器位阶”继续提供位阶与经验曲线，附魔耐久插件保留。
旧的固定每级属性加成不再叠加。

每个存档槽首次加载时，对背包、仓库、保险物品和已保存商店中的旧枪执行一次初始化。
迁移前保存原存档副本，并把每把枪的 UUID 和抽取结果先写入迁移计划；计划写好后才修改存档。
确认这些记录已实际写入存档文件，才将迁移记为完成。中断重试会使用原计划中的相同结果，不重新随机。

迁移计划与备份位于 `BepInEx/config/RandomWeaponProgression/`，例如：

- `migration-slot5.json`：一次性迁移状态和原始结果。
- `before-migration-slot5-*.sss`：迁移前副本。

迁移完成后，如果旧武器缺少或损坏了记录，只报告缺失，不按照型号或当前属性重新编号，不自动修复或重抽。
因此请不要随意删除这些迁移状态文件。若恢复的是升级前旧存档，应连同相应的插件备份一起恢复，避免迁移状态与存档不一致。

已经验证过的单枪试验记录会保留原 UUID 和原先额外的 10% 伤害，面板单列为“试验继承”。
原有等级也会得到逐级随机收益，写入武器自己的升级记录。

## 保存与生成

编号、初始五项、逐级收益、固定版本的随机状态与出生规则一并编码，随每把枪的 `InventoryData.identifier` 保存。
读档仅解码和恢复；不把重建游戏对象当成生成新枪。
真实新枪在实际库存创建或世界掉落生成时初始化；说明面板中的临时预览不生成编号。
世界掉落的生成记录在拾取时沿用，拾取失败不会重新随机。
普通保存、仓库、丢下再拾取和属性对象替换均沿用同一条记录。
新掉落尚未拾取前只在当前游戏对象中保留记录，是否跨退出保留地面物品仍由原版游戏决定。

`identifier` 是当前版本的旧兼容字段，本插件保留原字符串以供迁移。游戏更新或安装其他复用此字段的插件后需要重新验证。

## 验证

自动检查覆盖随机范围、独立编号、逐级/跳级一致、重复读档不重抽、累计收益、其他修正器共存、失效记录不补写、试验迁移、原始存档 JSON/GZip 往返和补丁目标。
游戏启动还会用真实 Unity JsonUtility 自检，连续 3 次往返检查完整记录一致。
实际游戏的面板布局、新旧武器迁移和保存重载仍需运行验证，自动检查不能代替这些步骤。

```powershell
# 在仓库根目录执行：
.\build.ps1 -GameRoot '你的 SULFUR 游戏目录'
.\test.ps1 -GameRoot '你的 SULFUR 游戏目录'
```

最后一次保存的落盘检查位于 `BepInEx/config/RandomWeaponProgression.status.txt`。
详细的初始化、升级和错误记录在 BepInEx 日志中。
